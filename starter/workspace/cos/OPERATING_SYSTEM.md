# Operating system

Read [STATE.md](STATE.md) first. The [working agreement](system/WORKING_AGREEMENT.md) is the shared law; this file governs cadence and coordination.

## Manual daily cycle

1. Morning compile: re-read current priorities, ranked backlog, product receipts/status, recent decisions/errors, yesterday's closeouts, and any bounded maintenance output. Re-derive material claims. Write a short brief and today's coordination spine with the [daily template](templates/daily.md).
2. Human assessment: record rulings, including scope and ceilings, through the register door. CoS ranks approved work and prepares batons. Agents proceed on already delegated work without manufacturing a new approval queue.
3. Working sessions: read today's spine at open; product sessions verify and implement batons in owned worktrees. Product returns facts and evidence; CoS reconciles them. One owner edits the daily file; concurrent sessions file their own receipts rather than racing on it.
4. Close: update durable state, dated records, pending work, and scoped memory pointers. File failures by class with an enforcer or owner. Park inventions with triggers.
5. Evening review and research: use the [job contracts](system/jobs/README.md) manually under configured scope, or connect them to a separately approved external runner later. Review error classes into improvements, re-derive backlog priority, complete qualified low-risk CoS tasks, and research questions that earn depth for morning consumption. Never replay an old agenda without checking what changed.

The CoS controls depth: ship-fast or invent-and-test-deep, with the reason stated. Explicit founder research requests and justified proactive questions both enter that judgment. Select for decision value, suitability without live human judgment, freshness, and depth versus cost. Keep the human brief consequence-first; put detailed provenance in linked artifacts.

The [learning loop](system/learning-loop.md) is a standing workflow: logging is followed by class review, owned backlog work, an enforcer or explicit deferral, verification, and refreshed read paths. The morning brief distinguishes a suggested fix from a verified change.

## If automation is added later

No job is installed by this starter. The [portable contracts and configuration](system/jobs/README.md) define the evening review, deep research, and morning compile. They specify inputs/outputs, per-task authority, runtime limits, conflict handling, liveness, and stops in one place. Use them instead of copying operating instructions into each scheduler. Run and inspect a complete first cycle manually before any separately approved schedule. The external runner's permissions and limits must enforce the contract; these files do not.

## Weekly reflection

Has STATE changed? Did outcomes move? Are we re-escalating old blockers or repeating a failure class? What recurring human task should agents take over? What should be killed? Route the answer into the queue, a decision, an enforcement artifact, or a parked trigger; reflection without an updated read path will not help the next session.
