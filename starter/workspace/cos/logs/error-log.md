# Errors and learning register

This register deliberately starts empty: no real incidents or previous company's history are included. Every CoS, product, research, or unattended session logs failures, surprises, and near-misses here, including the diagnosis when a fix must wait.

Use the [entry body](../templates/error-entry.md), then the canonical [register door](../system/register.py) in `error` mode. Preserve earlier entries; a recurrence or correction gets a new linked note. Root cause may be unknown. Deep product forensics stay with product and link here.

An entry is the start of the [learning loop](../system/learning-loop.md): review recurring classes -> owned backlog improvement -> enforcer or explicit deferral -> verification -> follow-up entry and refreshed queue. CoS owns that review. A dated review should say which classes were checked, what was confirmed/rejected, and which backlog items or fixes resulted.
