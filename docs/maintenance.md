# Maintenance contract

This repository distributes a clean template. Its operational child directories are examples to copy, not current company state.

Keep shared rules in [WORKING_AGREEMENT.md](../starter/workspace/cos/system/WORKING_AGREEMENT.md), coordination rules in [CoS instructions](../starter/workspace/cos/INSTRUCTIONS.md), and execution rules in [product instructions](../starter/workspace/product/INSTRUCTIONS.md). Entrypoints must remain thin. Change the canonical rule rather than patching both tools separately.

Do not introduce real people, business history, machine paths, secrets, provider permissions, or production identifiers. Examples must say they are fictional. Validate internal links, entrypoints, and the register helper after relevant changes. Review the diff and generated artifacts before any later publication. Selecting a license, installing integrations, and publishing require separate owner decisions.

These are instructions for agents, not an access-control system. Runtime permissions, review gates, and production safeguards must enforce actual boundaries in each project.
