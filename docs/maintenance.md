# Maintenance contract

This repository distributes a clean template. Its operational child directories are examples to copy, not current company state.

Keep shared rules in [WORKING_AGREEMENT.md](../starter/workspace/cos/system/WORKING_AGREEMENT.md), coordination rules in [CoS instructions](../starter/workspace/cos/INSTRUCTIONS.md), and execution rules in [product instructions](../starter/workspace/product/INSTRUCTIONS.md). Entrypoints must remain thin. Change the canonical rule rather than patching both tools separately.

Keep real people and private business history out of examples; retain the explicitly approved copyright attribution and public repository metadata. Do not introduce machine paths, secrets, provider permissions, or production identifiers. Examples must say they are fictional. Validate internal links, entrypoints, license-notice retention, and the register helper after relevant changes. Review the diff and generated artifacts before publication. Revising licensing, installing integrations, and publishing require applicable owner authority.

The canonical legal notice is [LICENSE](../LICENSE). Each starter repo intentionally carries an identical `HARNESS_LICENSE` so independent copies preserve the MIT notice. Update them together and run the validator; do not treat those required notices as duplicated operating policy.

These are instructions for agents, not an access-control system. Runtime permissions, review gates, and production safeguards must enforce actual boundaries in each project.
